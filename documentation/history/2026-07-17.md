# 2026-07-17

## Release workflow port

- Ported the fixed two-phase release workflow from `obsidian-remarkable-sync` (verbatim copy of its `.github/workflows/release.yml`). The old shared workflow built and attested artifacts at the triggering commit, then created the version-bump commit and tag — so the build-provenance attestation was bound to the wrong commit and the community-catalog review rejected releases ("attestation failed cryptographic verification").
- New design: a "prepare" job (dispatch on a branch) bumps versions, generates the changelog, commits, and creates a lightweight tag behind a `bun run build` + `bun test` gate, then re-dispatches the workflow at the tag ref with `publish=true`; a "publish" job (dispatch-at-tag or bare tag push) builds, attests (`continue-on-error` removed), and creates the release with `github.sha` == tag commit. Design proven live on remarkable-sync 1.5.0 (cert sha == tag commit).
- `bun test` kept in the release gate (70 tests pass); `docs/release-notes.md` kept in the workflow's `git add` list (generated by `scripts/generate-changelog.ts`).
- Updated the "The GitHub workflow will:" summary in `scripts/release.sh` to match the two-phase flow.
